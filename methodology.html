WHY THIS MODEL EXISTS

Knowing what you actually have, before you ask the world to recognize it

A working assessment methodology for traditional orchards and agricultural landscapes, built to answer one honest question: are we actually ready, and if not, what specifically is missing?

The problem this model answers

A community, a researcher, or a student working on a heritage nomination usually has two bad options: read UNESCO's own dense procedural documents cover to cover, or guess. Neither tells you, plainly, whether a specific piece of evidence is strong enough, or what a real reviewer would actually ask for next.

This model exists to close that gap. It takes UNESCO's own official assessment structure, the Operational Guidelines for the World Heritage Convention and the Operational Directives for the 2003 Intangible Cultural Heritage Convention, and turns it into sixteen concrete stages, each with a real question, a real example, and an honest status: ready, needs evidence, or not yet started.

What the model actually does

Three things, working together, not three separate features.

It routes a site to the right path

World Heritage, ICH Representative, and ICH Urgent Safeguarding are three different conventions with three different bars to clear. The model tracks a site against all three simultaneously, and is honest when the strongest path isn't the one with the highest percentage, a single failed gatekeeper (missing community consent, for example) overrides everything else.

It tells you what's missing, specifically

Not "40% complete." A real, generated summary: which stages are fully documented, which have never been touched, and, for each unanswered question, what a genuinely strong answer would actually contain, pulled directly from the same guidance UNESCO reviewers themselves use.

It tells the difference between a lead and evidence

A newspaper mention is not the same as a verified citation. Every piece of information in this model carries an honest tier, verified, lead, or genuinely unread, and a lead can never on its own mark a question Ready. This discipline is the difference between a model that looks complete and one that actually is.

Why these four reference cases, specifically

Not chosen as interesting examples. Each was reverse-engineered from a real, specific question Mi'ilya's own case raised, then studied from primary sources, the actual nomination dossiers and Committee decisions, not secondhand summaries, to find out what a real reviewer actually asked for.

ICH Representative

Al-Mihrass, Jordan

The closest possible precedent: same region, same subject, ancient olive trees, same path. Studied to learn exactly what a successful file looks like, criterion by criterion.

World Heritage, emergency

Sebastia, Palestine

An active, still-pending emergency nomination. Studied to understand what a threat-driven case looks like, and what real urgency actually requires in a dossier.

ICH Urgent Safeguarding

Turkish olive cultivation

A genuinely different threat framing: production stays viable while the traditional knowledge itself erodes. Studied to learn that distinction precisely.

World Heritage, landscape

Serra de Tramuntana, Spain

The specific precedent behind Mi'ilya's own combined winery-and-orchard question. Read directly from the actual ICOMOS evaluation, revealing a harder, more honest standard than expected.

An AI-assisted research workflow, not automatic data entry

The model doesn't ask a community to type facts into a form and hope for the best. Real primary sources, nomination dossiers, Committee decisions, academic papers, are read directly, extracted, tagged with an honest confidence tier, and cited. When a written recommendation doesn't exist yet for a path, the model generates one from the real underlying data rather than leaving a blank.

This is the actual answer to a real question worth asking directly: can this model do the reading and analysis itself, not just hold a folder of files? Within a supervised, source-checked workflow, yes, this is what happened across every reference case in this project.

Where this can go

Nothing in this model is Mi'ilya-specific. The stage structure, the evidence discipline, the auto-generated summaries, and the three-path guidance were built to onboard any orchard or heritage-tree site, anywhere, olive, date palm, fig, pomegranate, grapevine, and walk it through the same rigorous path toward UNESCO readiness. Mi'ilya is the first real case this framework was built against, not the limit of what it can hold.

  • A new site is one row in the database, not a schema change.
  • The same sixteen stages, the same evidence-tier discipline, and the same auto-generated guidance apply immediately.
  • A research team studying multiple heritage-tree sites could use this as a shared, standing readiness tracker across all of them at once, not a one-off tool built for a single case.
